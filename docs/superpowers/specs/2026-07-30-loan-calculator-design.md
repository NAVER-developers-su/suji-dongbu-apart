# 수지동부아파트 리모델링 대출 계산기 — 설계

작성일 2026-07-30

## 배경

수지동부아파트 리모델링 조합원은 두 종류의 대출을 받을 수 있다. 한도는 세대마다 다르고
(감정평가액·분담금이 612세대 모두 다름), 금리와 이자 계산 방식은 아직 조합 확답이 오지
않았다. 조합이 배포한 엑셀 계산시트는 세대 정보를 손으로 옮겨 적어야 하고, 가정을 바꿔가며
비교해 볼 수단이 없다.

이 프로젝트는 동·호수만 고르면 내 세대의 한도와 이자를 바로 보여주고, **확정되지 않은
가정을 열어놓고 경우별로 비교**할 수 있는 GitHub Pages 정적 페이지를 만든다.

주 사용 환경은 **모바일**이다.

## 데이터

`분담금.json` — 2026년 정기총회 책자 303~319쪽(사진 17장)에서 판독한 612세대 전량.

동 101~106 × 층 1~17 × 호 1~6 = 612세대. `호수`는 `층*100 + 호` 문자열(1층 4호 → `"104"`).

```json
{ "제목": "...", "비례율": "109.10%", "세대수": 612,
  "세대": [ { "타입": "72E", "동": "106", "호수": "1504",
    "전용면적_m2": 72.24, "공급면적_m2": 94.25,
    "종전평가금액": { "삼창감정평가법인": …, "대화감정평가법인": …, "종전평균": 651950000 },
    "종후평가금액": { "삼창감정평가법인": …, "대화감정평가법인": …, "종후평균": 1098550000 },
    "권리가액": 711278000, "분담금": 387272000, "페이지": 317 } ] }
```

판독 정확도는 네 가지 산술 항등식으로 612행 전량 검증했다: 종전평균·종후평균이 두 감정평가
법인 값의 정확한 평균인지, 권리가액이 종전평균×1.0910과 일치하는지(실효 비례율
109.1000~109.1002%로 수렴), 분담금이 종후평균−권리가액인지. 동+호수 중복 0건, 층 누락 0건.
별도 촬영본으로 317쪽을 교차 확인해 일치를 확인했다.

## 계산 근거

### 한도 — 「추가사업비 대여 신청 최종 신청서」

```
대출가능 총액        = 종후 감정평가액 × LTV 90%
이주비 대출 한도      = 종전 감정평가액 × LTV 60%   (2025.10.15 이후 매수 → 40%)
잔여한도             = 대출가능 총액 − 이주비 신청액 − 분담금
                       (이주비 미신청 시 이주비 신청액 자리에 기존 주담대 실제 잔액)
추가사업비 원금한도    = 잔여한도 ÷ (1 + 연이율 ÷ 12 × 개월수)      ← 십만원 절사
```

마지막 줄이 핵심이다. 추가사업비는 **원금과 이자를 합한 금액을 신청**하는 구조라, 한도라는
버킷 안에 원금과 만기까지의 이자가 함께 들어간다. 그래서 실제로 손에 쥘 수 있는 원금은
한도를 이자계수로 나눈 값이다.

### 이자 — 조합 공식 계산시트

```
추가사업비 이자 = 원금 × 5.28% ÷ 12 × 55개월 = 원금 × 24.2%     ← 십만원 올림
```

순수 월할 단리다. 날짜·일수 개념이 없고 기산일도 없다. 금리 5.28% = CD(91일물) 2.92% +
가산 2.22% + 취급수수료 0.14%이며, 취급수수료는 이미 금리 안에 포함되어 별도로 더하지 않는다.
"3개월 변동금리"는 CD 재설정 주기를 뜻할 뿐 복리 주기가 아니다.

### 미해결 — 이자의 이자

조합이 구두로 안내한 "1억당 대출금 이자 2,672만원 + 이자의 이자 57만원"은 공식 계산시트
어디에서도 재현되지 않는다. 시트대로면 1억당 2,420만원이고 이자의 이자 항목 자체가 없다.

두 숫자는 **동시에 성립할 수 없다.** 복리주기(1·3·6·12개월) × 기간(1~120개월) × 금리
(2~10%, 0.001% 간격) 480만 조합을 전수 대입해도 일치하는 조합이 없다. 이자의이자/원금이자
비율 2.13%는 20~30개월짜리 대출의 비율인데, 2,672만원은 55개월 이상에서 나오는 금액이라
서로 모순이다. 개별로 보면 2,672만원은 5.28%에 60.7개월 또는 55개월에 5.83%가 필요하고,
57만원은 1억을 4.5%로 30개월 굴렸을 때의 이자의이자 규모다.

다만 두 값의 **합** 2,729만원은 55개월 월복리 총액 2,731만원과 0.08% 차이다. 총액은 맞고
분해가 잘못 전달됐을 가능성이 있다.

**결론: 하나의 값을 못박지 않는다.** 이자 계산 방식을 단리 / 3개월 복리 / 월복리 중에서
고르게 하고, 단리 대비 초과분을 "이자의 이자"로 분리 표시한다. 조합 확답이 오면 그때 기본값을
바꾼다.

## 화면

모바일 1단, 900px 이상에서 2단(좌 입력 / 우 결과 sticky).

```
머리말
세대 선택      동 ▾  층 ▾  호 ▾           ← 드롭다운 3개
감정평가 타일   종전 / 종후 / 권리가액 / 분담금
매수 시점      라디오 4개
대출 신청 금액  이주비 · 추가사업비 (각각 입력 + 한도 미터)
상세 설정      (접힘)
계산 결과      만기 총 상환액 + 내역
경우별 비교     표 3개
꼬리말
[하단 고정 바]  총 이자 · 만기 총 상환액 · [결과]    ← 모바일 전용
```

### 매수 시점 (라디오 4)

| 값 | 표기 | 동작 |
|---|---|---|
| `ltv60` | 2025.06.27 이전 매수 | 이주비 LTV 60% |
| `consult` | 2025.06.28~10.14 매수 | 한도 자리에 "상담 필요" 표시, 초과 경고 안 함 |
| `ltv40` | 2025.10.15 이후 매수 | 이주비 LTV 40% |
| `none` | 이주비 미신청 | 이주비 입력 비활성, 기존 주담대 잔액을 대신 차감 |

### 상세 설정 — 확정 전 가정을 전부 연다

CD 91일물(2.92%), 이주비 금리(4.50%), 기간(55개월), 종후 LTV(90%), 이주비 LTV(60%),
기존 주담대 잔액, 이자 계산 방식(단리/3개월 복리/월복리), 십만원 단위 절사·올림(적용/미적용).

가산 2.22%와 취급수수료 0.14%는 고정 상수다. 추가사업비 금리는 `CD + 2.22 + 0.14`로 자동
계산되고 내역을 함께 보여준다.

### 경우별 비교 — 이 페이지의 목적

| 표 | 행 | 열 |
|---|---|---|
| 1 | LTV 60% / 40% / 미신청 | 이주비 한도 · 잔여한도 · 추가사업비 원금한도 · 실수령 합계 |
| 2 | 단리 / 3개월 복리 / 월복리 | 이주비 이자 · 추가사업비 이자 · 이자의 이자 · 총 이자 |
| 3 | CD ±0.50 / ±0.25 / 기준 | 적용 금리 · 원금한도 · 추가사업비 이자 · 총 이자 |

현재 설정에 해당하는 행은 강조하고 `현재` 배지를 단다.

## 계산 모듈

```
factor(r, method) =
  단리       r/12*n
  3개월복리   (1 + r/4)^(n/3)  − 1
  월복리      (1 + r/12)^n     − 1

이자의 이자 = 원금 × (factor(method) − factor(단리))
```

이자의 이자를 별도 항으로 두지 않고 **복리 총액에서 단리분을 뺀 나머지**로 정의한다. 단리를
고르면 자동으로 0이 되므로 조합 시트와 숫자가 정확히 일치한다.

십만원 단위 처리는 시트를 따른다. 한도는 절사(`Math.floor`), 신청액 이자는 올림
(`Math.ceil`). 토글을 끄면 원 단위로 계산한다.

## 구성

```
index.html    구조
styles.css    디자인 토큰 + 컴포넌트 (모바일 퍼스트, 라이트/다크 양쪽)
app.js        계산 + 렌더링
분담금.json    612세대 데이터
README.md      프로젝트 설명 · 데이터 출처 · 면책
```

빌드 도구·프레임워크·외부 의존성 없음. GitHub Pages에 그대로 올린다. `app.js`는
`window.__DATA__`가 있으면 그것을, 없으면 `분담금.json`을 `fetch`한다. 이 분기 덕분에
`build_preview.py`가 전부 인라인한 단일 파일 미리보기를 만들 수 있다.

로컬에서 열 때는 `fetch` 때문에 `python3 -m http.server`가 필요하다.

## 디자인

- **색** — 청록 잉크 `#0E6B66`가 정체성이자 "정상" 상태를 겸한다. 한도 근접은 황토
  `#B07514`, 초과는 적색 `#B23A2F`만 예외적으로 등장해 경고가 눈에 띈다. 중성색은 순회색
  대신 청록 쪽으로 살짝 치우친 계열.
- **서체** — 한글은 시스템 고딕 스택(Apple SD Gothic Neo / Pretendard / 맑은 고딕),
  금액은 전부 모노스페이스 + `tabular-nums`. 돈과 말을 서체로 분리해 계기판처럼 읽히게 한다.
  한글 웹폰트는 용량 때문에 인라인이 불가능하므로 시스템 폰트가 정직한 선택이다.
- **레이아웃** — 모바일 1단이 기본. 탭 타깃 최소 46px, 하단 고정 요약 바로 스크롤 없이 결과
  확인. 표는 가로 스크롤 컨테이너에 넣어 본문이 옆으로 밀리지 않게 한다.
- 라이트/다크 모두 토큰 단위로 정의하고 `prefers-color-scheme`과 `data-theme`을 모두 지원한다.
